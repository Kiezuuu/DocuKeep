DOCUKEEP UPGRADE PACKAGE

Files:
- docukeep_index_fixed.html: updated frontend; deploy this as index.html in the existing site root.
- docukeep_migration.sql: additive Supabase migration. Run AFTER the existing base setup SQL. Do not rerun the old base SQL after this migration because it would restore the old signup trigger and old staff UUID.
- sw.js: service worker; place in the same site root as index.html.
- manifest.webmanifest: PWA manifest; place in the same site root.
- icons/icon-192.png and icons/icon-512.png: PWA icons; keep the icons folder beside the manifest.

SUPABASE STEPS
1. Back up the Supabase project/database first.
2. Open Supabase SQL Editor for the existing project.
3. Run docukeep_migration.sql as the project owner.
4. Confirm the staff profile exists with UUID 4e6c5f42-e751-4fa3-ad92-5746d9ee8323, role=staff, status=approved.
5. Keep the docukeep-files bucket private. The existing 25 MB per-file limit is retained.
6. In Supabase Cron, schedule: select public.generate_docukeep_deadline_notifications(); once daily. The function inserts 7-, 3-, and 1-day reminders idempotently.
7. Deploy the HTML under the filename index.html, plus sw.js, manifest.webmanifest, and icons/ on HTTPS. Service workers require HTTPS (localhost is also supported).
8. Test with one new student Gmail registration, approve it using the staff account, then sign in as that student.

IMPLEMENTED IN THIS PACKAGE
- Signup trigger no longer blocks manually provisioned staff Auth users; public student/teacher signups still create pending profiles and enforce their email domains.
- Existing profile/document tables, private bucket, and base architecture are retained.
- Additive folder, notification, entitlement, group-sharing, document-access, and upload-sync tables with RLS.
- Student folder creation/color persistence and folder assignment on upload.
- Multiple file selection, SHA-256 duplicate warning, and local IndexedDB offline upload queue with online retry.
- PDF and image preview, signed download links, PWA shell caching, offline indicator, and deadline notification SQL function.
- Student-facing status labels include Submitted and Overdue based on due date.

IMPORTANT LIMITATIONS / REQUIRED INFRASTRUCTURE
- This package has NOT been tested against your live Supabase project; the environment cannot authenticate to your project or execute its SQL remotely. JavaScript syntax was checked locally only. Apply the migration in a backed-up project and run the test plan before production use.
- Offline mode caches the app shell and queues selected file blobs in IndexedDB. Authenticated dashboards, database reads, signed URLs, and previews still require internet. A browser/device storage quota can limit offline file size.
- Deadline reminders are generated by the SQL function only when Supabase Cron invokes it. Configure the daily schedule as described above. Browser notifications/email/push delivery are not configured.
- 128 GB Premium capacity is NOT activated. The current Storage bucket still enforces the existing 25 MB per-file cap. A billing provider, verified subscription webhook, entitlement enforcement, and approved bucket limits are required before selling/enabling Premium.
- Group tables and RLS foundations are included, but a complete group-management/share/revoke interface is not included. Do not advertise group sharing as finished yet.
- SHA-256 duplicate detection warns before uploading; it does not delete files. Review and deletion workflows still need an explicit user-confirmed UI.
- DOCX preview is not enabled; unsupported formats receive a download message. PDF and common image previews are supported.
- Bulk upload runs sequentially and reports processing counts; per-file byte-level progress bars are not implemented.
- Folder colors are saved in Supabase; folder rename/delete and moving existing files are not included in this frontend update.

USER ROLE MANAGEMENT UPDATE (NOV 11, 2026)
- The updated frontend adds a User Role Management table inside Staff Administration.
- Approved staff can search/filter profiles and change another account between student, teacher, and staff.
- Role changes call the protected manage_docukeep_user_role() database function; the browser cannot directly update profile roles.
- The function validates Gmail for students and @deped.gov.ph for teachers, automatically approves accounts promoted to staff, prevents self-role changes, and prevents demoting the last approved staff account.
- Run docukeep_role_management.sql in Supabase SQL Editor once before using the new role controls. Alternatively, this function is included at the end of docukeep_migration.sql.
- Replace the deployed index.html with docukeep_index_fixed.html (rename it to index.html).
